# Contributing to Awesome Ergo

Thanks for helping keep Awesome Ergo useful for the Ergo community. This repository is a curated list, so contributions should make the list easier to trust, browse, and maintain.

## Setup

1. Fork and clone the repository.
2. Create a branch for your change.
3. Edit `README.md` or supporting documentation.
4. Review the rendered Markdown before opening a pull request.

No build step is required for normal list updates.

## What To Add

Good additions are active, public resources that are directly useful to Ergo users, builders, miners, wallet developers, or ecosystem researchers.

Before adding a link, check that:

- the project or resource is related to Ergo;
- the URL resolves successfully;
- the project is active or clearly marked as archived, experimental, or historical;
- the entry fits the existing category structure;
- the description is neutral, concise, and fact-based.

If a project belongs in a new category, explain why the category helps readers find related resources.

## Entry Style

Use the existing list style:

```markdown
- [Project Name](https://example.com) - Short factual description. [`Language`] *(Status)*
```

Keep descriptions short. Avoid marketing language, referral links, tracking links, and unverifiable claims.

## Pull Request Checklist

Before opening a PR:

- confirm all new or changed links work;
- keep entries alphabetized or grouped consistently when the surrounding section uses an order;
- avoid duplicate entries already present elsewhere in the list;
- keep formatting consistent with nearby entries;
- include a short PR summary that explains what changed and why.

For link-only or docs-only changes, mention how you verified the updated links.

## Not a Fit

The following changes are usually not accepted:

- unrelated blockchain or crypto resources;
- paid promotions without clear community value;
- duplicate links to the same project;
- projects with no public information or inaccessible documentation;
- broad rewrites that mix formatting churn with content changes.

When in doubt, open a small PR with context so maintainers can review it quickly.
